────────────────────────────────────────────────────────────────────────────
FRAMEWORK SPECIFICATIONS
────────────────────────────────────────────────────────────────────────────

CLIENT (framework/client.js)
  - Single HTTP client wrapping all API calls
  - Automatically attaches auth token from state
  - Logs every request and response (method, url, payload, status, body)
  - On 401: auto-refreshes token and retries once
  - On 5xx: retries up to 3 times with exponential backoff
  - Captures response time for every call
  - Throws a typed ApiError with context on failure

LOGGER (framework/logger.js)
  - Structured output with levels: INFO, STEP, PASS, FAIL, WARN, DEBUG
  - Every log line includes: timestamp, scenario name, step number, message
  - Color-coded terminal output
  - Simultaneously writes to: /tests/logs/run_[timestamp].log
  - Step timer: logs duration of each step automatically
  - On failure: logs the full request, response, and DB state

  Output format for each step:
  ─────────────────────────────────────────────────────────────
  [14:23:01] [STEP 3/12] [Scenario: Purchase Flow]
             Action   : Convert PO-2024-0042 to Purchase Invoice
             API      : POST /api/purchase-invoices
             Response : 201 Created (342ms)
             Result   : ✅ PASS
             DB Check : AP balance increased by EGP 12,400 ✓
                        Inventory +50 units Laptop Pro @ EGP 248/unit ✓
                        GL: DR Inventory 12,400 | CR AP 12,400 ✓
  ─────────────────────────────────────────────────────────────

STATE STORE (framework/state.js)
  - Central in-memory store for all IDs and references created during the run
  - ZERO hardcoded IDs anywhere in the test suite
  - All IDs flow from API responses into state, then consumed by next steps
  - Structure:
      state.tenant       → { id, name, branchIds[], fiscalYearId }
      state.accounts     → { arId, apId, inventoryId, revenueId, cogsId, cashId, ... }
      state.products     → { [productKey]: { id, unitIds[], priceListIds[] } }
      state.suppliers    → { [key]: { id, name } }
      state.customers    → { [key]: { id, name } }
      state.purchases    → { [key]: { poId, invoiceId, paymentId } }
      state.sales        → { [key]: { invoiceId, paymentId } }
      state.employees    → { [key]: { id, payrollId } }
      state.snapshots    → { before: {}, after: {} }  ← DB snapshots

DATA FACTORY (framework/dataFactory.js)
  - Generates realistic, randomized data for every entity
  - NO static strings like "Test Supplier 1" — use real-looking generated data
  - Generators:
      generateTenant()     → { name, taxId, address, currency, ... }
      generateProduct()    → { name, sku, category, cost, price, ... }
      generateSupplier()   → { name, email, phone, currency, paymentTerms, ... }
      generateCustomer()   → { name, email, creditLimit, currency, ... }
      generateEmployee()   → { name, nationalId, hireDate, department, ... }
      generateReference()  → unique document reference (e.g. PO-2024-XXXX)
  - Use a seeded random so runs are reproducible when needed
  - Supports locale-aware data (Arabic names, Egyptian tax IDs, etc.)

RUNNER (framework/runner.js)
  - Executes scenarios sequentially (Scenario 1 → 2 → 3 → ... → 7)
  - Each scenario is a list of named steps
  - Each step has: name, action (async function), assertions (async function)
  - On step failure: logs the error, marks scenario as failed, continues to next step
  - Does NOT abort the entire suite on one failure
  - Tracks: passed steps, failed steps, skipped steps (due to dependency failure)
  - After all scenarios: prints the summary report to console

PHASE 3 — BUILD THE ASSERTION LAYER
══════════════════════════════════════════════════════════════════════════════

Assertions are the heart of this suite.
Each assertion queries BOTH the API and the database directly,
then compares the actual state against the expected state.

────────────────────────────────────────────────────────────────────────────
accountingAssertions.js

  assertDoubleEntry(journalEntryId)
    Query the journal entry lines from the DB
    Sum all debit amounts, sum all credit amounts
    Assert: totalDebits === totalCredits (to the cent)
    Assert: at least 2 lines exist
    Log: each line (account, debit, credit, currency)

  assertAccountBalance(accountId, expectedBalance, currency)
    Query the account balance from the API
    Query the sum of all GL entries for this account from the DB
    Assert: API balance === DB computed balance === expectedBalance
    Tolerance: 0.01 (rounding only)

  assertTrialBalance()
    Call trial balance API
    Query DB: sum all debit lines, sum all credit lines
    Assert: API total debits === DB total debits
    Assert: API total credits === DB total credits
    Assert: total debits === total credits
    Log: every account that has a non-zero balance

  assertJournalCreatedFor(sourceDocument, sourceId)
    Query DB for journal entries linked to this source document + ID
    Assert: at least one journal entry exists
    Assert: the journal is posted (not draft)
    Assert: debits = credits on each entry

  assertAccountMovement(accountId, expectedDelta, direction)
    Take a before-snapshot and after-snapshot of the account balance
    Assert: the difference matches expectedDelta in the correct direction
    (direction = 'debit' or 'credit')

────────────────────────────────────────────────────────────────────────────
inventoryAssertions.js

  assertStockLevel(productId, branchId, unitId, expectedQty)
    Query stock from API
    Query stock from DB (inventory movements table sum)
    Assert: API qty === DB qty === expectedQty
    Log: all recent movements for this product

  assertStockMovement(productId, expectedDelta, direction)
    Snapshot before and after
    Assert: difference = expectedDelta in the correct direction
    Assert: a stock movement record exists in DB with correct type

  assertInventoryValueInGL(expectedValue)
    Get inventory GL account balance
    Get inventory valuation report total (qty × cost per product)
    Assert: GL balance === valuation report total
    Log: any product where unit cost × qty ≠ GL contribution

  assertNoNegativeStock(branchId)
    Query all product stock levels for this branch
    Assert: no product has qty < 0
    Log: any product near zero

────────────────────────────────────────────────────────────────────────────
arApAssertions.js

  assertAPBalance(supplierId, expectedBalance)
    Query open payables for this supplier from API
    Query DB: sum open bill amounts − payments for this supplier
    Assert: API === DB === expectedBalance

  assertARBalance(customerId, expectedBalance)
    Query open receivables for this customer from API
    Query DB: sum open invoice amounts − receipts for this customer
    Assert: API === DB === expectedBalance

  assertInvoicePaid(invoiceId)
    Query invoice status
    Assert: status = paid or closed
    Assert: outstanding balance = 0

  assertPaymentAllocated(paymentId, invoiceId, amount)
    Query payment allocations from DB
    Assert: an allocation record links this payment to this invoice
    Assert: allocated amount = expectedAmount

────────────────────────────────────────────────────────────────────────────
payrollAssertions.js

  assertNetPay(payrollId, expectedGross, expectedDeductions, expectedNet)
    Query payroll entry from API and DB
    Assert: gross = expectedGross
    Assert: total deductions = expectedDeductions
    Assert: net = gross − deductions = expectedNet
    Tolerance: 0.01

  assertPayrollGLEntries(payrollId)
    Query GL entries linked to this payroll run
    Assert: salary expense account debited by gross amount
    Assert: tax payable account credited by tax withheld
    Assert: social insurance payable credited by SI amount
    Assert: payroll payable or cash credited by net pay
    Assert: all entries double-balanced

  assertDeductionApplied(payrollId, deductionType, expectedAmount)
    Query deduction lines for this payroll entry
    Assert: a line with deductionType exists
    Assert: amount matches expectedAmount

      purchaseService.addPOLine(po.id, {
        productId: state.products.p1.id,

  Assert:
    Invoice created with status = posted or draft
    Invoice linked to the original PO in DB

STEP 3.5 — Post Purchase Invoice
  Action:
    purchaseService.postPurchaseInvoice(state.purchases.main.invoiceId)

  Assert:
    Invoice status = posted

    — INVENTORY ASSERTIONS —
    expectedNewP1 = snapshot.before.inventoryP1 + 10
    expectedNewP2 = snapshot.before.inventoryP2 + 100
    assertStockLevel(p1, mainBranch, unit_piece, expectedNewP1)
    assertStockLevel(p2, mainBranch, unit_ream, expectedNewP2)

    — ACCOUNTING ASSERTIONS —
    invoiceValueUSD = (10 × 800) + (100 × 3.50) = $8,350
    invoiceValueBase = invoiceValueUSD × exchangeRate

    assertAccountMovement(
      state.accounts.inventoryId,
      invoiceValueBase,
      direction: 'debit'     ← inventory increased (asset up = debit)
    )
    assertAccountMovement(
      state.accounts.apId,
      invoiceValueBase,
      direction: 'credit'    ← AP increased (liability up = credit)
    )

    assertJournalCreatedFor('purchase_invoice', state.purchases.main.invoiceId)
    assertDoubleEntry(journalEntryId)

    — GL VERIFICATION —
    newInventoryGL = snapshot.before.inventoryGL + invoiceValueBase
    newAPBalance   = snapshot.before.apBalance   + invoiceValueBase
    assertAccountBalance(state.accounts.inventoryId, newInventoryGL)
    assertAccountBalance(state.accounts.apId, newAPBalance)

STEP 3.6 — Create Supplier Payment
  Action:

      type:       'supplier_payment',
      supplierId: state.suppliers.main.id,
      amount:     invoiceValueBase,
      currency:   base currency,
      date:       today,
      accountId:  state.accounts.cashId
    })
    paymentService.allocatePayment(payment.id, state.purchases.main.invoiceId, invoiceValueBase)
    state.purchases.main.paymentId = payment.id

  Assert:
    Payment record in DB with correct amount
    Allocation record links payment to invoice

    assertInvoicePaid(state.purchases.main.invoiceId)
    assertAPBalance(state.suppliers.main.id, 0)

    assertAccountMovement(state.accounts.apId, invoiceValueBase, 'debit')
      ← AP decreased (liability down = debit)
    assertAccountMovement(state.accounts.cashId, invoiceValueBase, 'credit')
      ← cash decreased (asset down = credit)

    assertJournalCreatedFor('payment', payment.id)
    assertDoubleEntry(paymentJournalId)

    — FINAL AP BALANCE —
    assertAccountBalance(state.accounts.apId, snapshot.before.apBalance)
      ← AP opened and fully closed = net 0 change from before
