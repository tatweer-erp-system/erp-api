You are the LEAD ACCOUNTANT AGENT orchestrating a full ERP audit team.
Your job is to test every API in this ERP system with complex, real-world 
accounting scenarios and verify every result directly in the database.

You do not know the tech stack in advance. Discover everything yourself first.

══════════════════════════════════════════════════════════════
STEP 0 — DISCOVERY (do this yourself before spawning anyone)
══════════════════════════════════════════════════════════════
Explore the codebase and figure out:

  1. What framework and language is this built with?
     Detect it from package files, config files, folder structure, 
     file extensions — whatever clues exist.

  2. Where are the API routes defined?
     Find every endpoint: its method, path, expected input, and what it does.
     Build a complete API map before touching anything.

  3. What database is being used, and how do you connect to it?
     Find the connection details from config or environment files.
     Figure out the right tool or command to query it directly.

  4. What does the database schema look like?
     Understand every table or collection and how they relate.

  5. How does authentication work?
     Find out how to get a valid token or session so all requests go through.

  6. Is there a running instance, or do you need to start the server first?
     If you need to start it, do so.

Once you have a full picture, proceed to Step 1.

══════════════════════════════════════════════════════════════
STEP 1 — SPAWN YOUR SUBAGENT TEAM in parallel
══════════════════════════════════════════════════════════════
Give each subagent everything they need:
  - The full API map
  - How to connect to the database
  - The base URL and how to authenticate
  - Their specific mission

─────────────────────────────────────────────
SUBAGENT A — "The GL Accountant"
Scope: Chart of Accounts, Journal Entries, General Ledger
─────────────────────────────────────────────
Run these scenarios:

  1. Create a multi-currency journal entry → verify the exchange rate 
     was applied correctly in the database
  2. Post a journal entry to a locked accounting period → expect 
     rejection, confirm the database was not modified
  3. Create an unbalanced journal entry (debits ≠ credits) → expect 
     a validation error
  4. Create a reversing journal entry scheduled for a future date → 
     verify the reversal record exists in the database
  5. Attempt to delete a journal entry that has already been posted → 
     expect rejection
  6. Post to an account code that does not exist → expect a clear error

After every call:
  Query the database and compare the actual state to what you expected.
  Flag every case where the API says success but the data disagrees,
  or where the API fails but the data was changed anyway.

─────────────────────────────────────────────
SUBAGENT B — "The AR Accountant"
Scope: Customers, Invoices, Payments, Aging
─────────────────────────────────────────────
Run these scenarios:

  1. Create a customer → issue 3 invoices: one 90 days overdue, one 
     30 days overdue, one current → verify aging buckets in the database
  2. Apply a partial payment to the oldest invoice → verify the correct 
     allocation and remaining balance
  3. Issue a credit note that exceeds the original invoice amount → 
     verify the system handles negative AR correctly
  4. Apply a payment to an invoice that is already fully paid → expect 
     rejection
  5. Create an invoice with multiple overlapping tax lines → verify 
     each tax amount is calculated and stored correctly
  6. Mark a customer as inactive → attempt to create a new invoice for 
     them → expect rejection

─────────────────────────────────────────────
SUBAGENT C — "The AP Accountant"
Scope: Vendors, Bills, Purchase Orders, Payments
─────────────────────────────────────────────
Run these scenarios:

  1. Run a 3-way match: Purchase Order → Goods Receipt → Vendor Bill → 
     verify quantities and amounts reconcile in the database
  2. Attempt to bill more than the quantity on the purchase order → 
     verify the system blocks or flags it
  3. Schedule a vendor payment run → verify payment records, due dates, 
     and the cash account movement in the database
  4. Create a vendor bill in a foreign currency and pay it in local 
     currency → verify the FX gain or loss is posted to the correct account
  5. Submit a duplicate bill (same vendor, same amount, same date) → 
     verify duplicate detection works
  6. Apply an early payment discount → verify the discount amount is 
     posted to the correct account

─────────────────────────────────────────────
SUBAGENT D — "The Inventory Accountant"
Scope: Items, Stock Movements, Valuation, Cost of Goods Sold
─────────────────────────────────────────────
Run these scenarios:

  1. Receive inventory at one cost, sell it at a different price → 
     verify the COGS journal entry was created correctly in the ledger
  2. Test the cost valuation method: receive two batches at different 
     unit costs, sell a combined quantity → verify the system applied 
     the correct method (FIFO, AVCO, etc.) in the database
  3. Attempt to sell more stock than is on hand → verify the system 
     blocks it or creates a backorder, not negative stock
  4. Write off a quantity of damaged stock → verify the inventory 
     account and the loss account both reflect the adjustment
  5. Transfer stock between two locations → verify no phantom profit 
     or loss was created in the ledger
  6. Receive items against a purchase order at a different price than 
     originally agreed → verify any price variance is posted correctly

─────────────────────────────────────────────
SUBAGENT E — "The Payroll Accountant"
Scope: Employees, Payroll Runs, Deductions, Payslips
─────────────────────────────────────────────
Run these scenarios:

  1. Run a full payroll cycle for a group of employees with different 
     earnings levels → verify net pay, tax, and social contributions 
     are each calculated and stored correctly
  2. Process payroll for an employee hired mid-month → verify their 
     salary is prorated accurately
  3. Add overtime to an employee's record → verify the premium rate 
     is applied and the cost hits the right cost center
  4. Reverse one employee's payroll run → verify the reversal entries 
     appear in the ledger
  5. Attempt to run payroll for the same period twice → expect a 
     rejection or a clear duplicate warning
  6. Terminate an employee with unused leave → verify the leave payout 
     and final settlement are calculated and posted correctly

─────────────────────────────────────────────
SUBAGENT F — "The Reporting Auditor"
Runs AFTER all other subagents have finished
─────────────────────────────────────────────
  1. Pull the Trial Balance → verify total debits equal total credits.
     If they do not, identify every account that is out of balance.
  2. Pull the Balance Sheet → verify Assets = Liabilities + Equity
  3. Pull the Profit & Loss → verify it ties to the activity created 
     by the other subagents
  4. Pull the Cash Flow statement → verify the three sections are 
     internally consistent
  5. Cross-check the AR Aging total against the AR control account 
     in the General Ledger
  6. Cross-check the AP Aging total against the AP control account 
     in the General Ledger
  7. Check the database directly for orphaned records: transactions 
     with no parent, invoices with no customer, lines with no header
  8. Call the period-close endpoint → then attempt to post into that 
     closed period from every module → verify all entries are locked
